\* vectors (1,536 B) + stored chunk text/metadata (~1 KB) = ~2.5 KB per vector. Disk/RAM use a further x1.3 for index overhead.

## 2. How to read this table honestly

* **Against Pinecone Serverless the saving is real but nowhere near 99%.** Its $50/month Standard minimum is the floor at all three scales for a lightly-queried index (storage + reads stay under $50 even at 10M vectors), so the comparison is a flat $50 against our cost.
* **Marginal vs dedicated.** If the vector store rides on a server you already run (here: the FastAPI container) the marginal cost is disk, i.e. cents. If you must provision a VM *for* the index, the saving at 10M vectors is about zero against Pinecone's minimum (last column).
* **Qdrant Cloud publishes no rate card** (usage-based on vCPU/RAM/disk; only a calculator), so only its free 1 GB tier is modelled: it covers 100K vectors at $0. Larger sizes are marked 'not published' rather than guessed (one third-party figure of ~$57/GB-RAM-month looked implausible and was discarded).
* An earlier draft used `$70 / $96 / $288` 'managed pod' baselines that were not traceable to a current price list; they are not used.

| Index overhead | x1.3 | assumption (IVF-PQ is smaller, HNSW larger) |

| EC2 us-east-1 on-demand | t4g.medium $24.53/mo (index <= 2 GB), t4g.large $49.06/mo | third-party aggregator; check aws.amazon.com/ec2/pricing |
| EBS gp3 / S3 Standard | $0.08/GB-mo (x1.5 headroom) / $0.023/GB-mo | AWS list prices |

| Replication / HA | none (single node) on the low-cost side | trade-off accepted, see below |

One-time Pinecone ingest write cost: 100,000 vectors = $1.06, 1,000,000 vectors = $10.62, 10,000,000 vectors = $106.25.

## 4. Trade-offs knowingly accepted

1. **Single node, no HA/replication.** A host failure means downtime until restore. The index is rebuildable from the corpus in minutes; keep a copy on S3.
2. **One writer at a time.** Embedded stores take a file lock; ingestion is serialised in-process.
3. **Ceiling on QPS and tail latency.** See `results_scale.json`; a managed in-memory index wins at high QPS and strict p99 SLAs.
4. **You own ops** (patching, backups, monitoring; see HANDOVER.md). The table excludes engineer time, which is the real cost of self-hosting.
5. **Local-mode Qdrant is brute-force** (no HNSW); fine at 100K, impractical at 1M+. Use a Qdrant server for larger indexes.
