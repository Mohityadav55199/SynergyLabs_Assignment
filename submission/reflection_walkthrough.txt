When a user submits a question on the Vercel frontend, the browser sends a POST request to /query on Render with the question, top_k, and an optional format filter. FastAPI validates the request and returns a 422 error if the input is invalid.
The question is converted into a 384-dimensional embedding using bge-small on the server CPU. LanceDB then searches for the closest chunks using cosine similarity, applying the format filter if one was selected.
One thing I like about this setup is the 0.68 similarity gate before the LLM call. If the best match scores below that threshold, the API returns a fixed message saying it doesn't have enough information. This saves token costs and avoids generating an answer from weak or irrelevant context.
If the results pass the gate, the retrieved chunks are added to a prompt that tells the model to answer only from the provided context and cite its sources. Groq runs Qwen at temperature 0, with a fallback model if the primary one is unavailable or rate-limited. The code then extracts the chunk citations used in the answer and returns them with the response and performance metrics.
In my test screenshot (the question was about HNSW), retrieval took 800 ms, and the total request took 1,378 ms. The response used 525 tokens and cited 2 chunks. Those numbers help show where the time went and how much context supported the answer.
The API logs the same metrics, and the frontend displays the answer, citation chips, and telemetry bar. The generation_mode field is useful because it tells me how the answer was produced—for example, whether it came from the normal LLM path (llm), was refused by the similarity gate without calling the LLM (no_context), or fell back to returning the raw top passage because the LLM was unavailable (extractive_fallback).
If I were improving the system, I’d focus on investigating why retrieval took 800 ms on Render when the same search takes about 20 ms locally (probably a cold or busy free-tier server), and measuring retrieval quality against a set of test questions. I’d also keep checking whether the similarity threshold rejects useful results or allows weak ones through.
